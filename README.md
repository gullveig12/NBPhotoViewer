# NEFViewer

本地 Windows 图片与 RAW 选片程序。Tauri 2 + Rust/LibRaw 0.22.2 + React。IDEA 可以直接打开本目录。

## 使用

0.5.5：批量模式中可按住鼠标左键，从一张照片拖到另一张后松开，追加选中两端及其间全部照片。拖动时预览高亮，不取消先前选择；上下边缘自动滚动，支持跨屏连选。轻微晃动仍是普通点击；Esc、窗口失焦或在照片范围外松开会取消本次拖动。

0.5.4：修正批量选择的普通点击行为。点击照片或勾选框均追加选中，再点取消该张，不清空其他已选照片；Ctrl 点击同样追加/取消。Shift 连选和 Ctrl+Shift 追加范围保持可用。

0.5.3：批量选择支持 Windows 式鼠标操作。单击照片本体选中一张；Shift 点击按本次完整照片顺序选中起点至终点（含屏幕外照片），连续 Shift 点击保持起点；Ctrl 点击追加/取消单张，Ctrl+Shift 追加一整段。勾选框仍直接追加/取消单张，也支持 Shift 连选。“选择已标记”“反选”“清空选择”、退出批量或更换来源会重置连选起点。

0.5.2：批量“导出”和“删除”按钮统一为紧凑等宽布局，随数量文字一起增宽，移除删除按钮过大的最小宽度。

0.5.1：批量操作栏的按钮统一显示为“导出（N）”和“删除（N）”，N 随当前勾选数量实时更新。

0.5.0：新增 JPEG 导出。详细页画布右键可“复制图片”或“将图片另存为 JPEG”；处理整张照片，不受缩放/平移影响，不把导出文件加入当前照片列表。复制在后台转换，并同时写入 Windows 剪贴板的 JPEG 与标准位图格式，供微信等应用选择其支持的格式；接收应用仍可能重新压缩。总览进入“批量选择”后，“导出”位于“删除所选”左边；选好保存文件夹后逐张转为 JPEG 并写入独立 ZIP，显示进度、完成路径和失败原因，可取消。

JPEG 固定质量 100、4:4:4，不主动缩小尺寸；质量 100 仍然有损，不是无损格式。普通图片使用原尺寸；RAW 优先使用相机大幅内嵌预览，预览明显偏小时尝试完整显影，显影失败会提示使用预览及可能较低的分辨率。详细页选择 RAW 显影时，复制/另存为也优先显影。PNG 等透明区域转为白色背景，动画/多页图片仅导出第一帧/页。保留可读取的主要拍摄 EXIF 与 ICC，旋转落到像素中并将方向标为正常；不会拷贝 MakerNote 或所有私有元数据。

每个 ZIP 的实际文件大小严格小于 1,000,000,000 字节（含文件目录和 ZIP 头），使用 Stored 打包，避免对已经压缩的 JPEG 再做无效压缩。超出上限的单张 JPEG 报错，不降低质量；失败项不影响其他照片。取消会在当前照片处理结束后生效，已完成的照片保存为可独立解压的 ZIP。原片和已存在的导出文件不会被覆盖，同名文件自动加序号。输出位于自己选的文件夹，导出过程中不要强制结束程序。

0.4.2：扩展缩略图加速。WebP 使用 libwebp 1.6.0 的缩小解码，TIFF/BMP 使用 Windows WIC 缩放，PNG/GIF 保留实测更快或兼容首帧行为的 Rust 解码。普通图片缩略图最多四个并发，按像素数估算内存占用，在 768 MiB 调度预算内排队；这不是整个程序的内存上限。相同照片合并请求，避免重复解码和缓存写入。动画 WebP 等特殊编码回退到兼容解码器。

RAW 内嵌大 JPEG 使用缩小解码，小预览直接读取。没有可用预览的 RAW 在独立通道按半尺寸、快速插值生成总览缩略图，不再阻塞其他 RAW 的内嵌预览，也不再为缩略图编码整幅 PNG。快速缩略图不会写入全尺寸预览缓存；详细页与 100% 检查仍使用原来的原图/完整显影流程。极大文件、缺少预览的 RAW 和特殊压缩仍可能超过零点几秒。

0.4.1：修复 JPG 总览首次加载慢。缩略图优先使用 Windows WIC 原生缩小解码，兼容路径使用 JPEG 1/8、1/4、1/2 缩小解码；最多四条生成通道，同一张照片请求合并并复用磁盘缓存。特殊 JPEG 的兼容解码单独限制并发。总览页只加载缩略图，进入详细后才读取原图与预加载相邻原图。此优化仅针对缩略图，详细页和 100% 仍显示完整原图。

0.4.0：可在同一来源混合浏览 JPG/JPEG、PNG、WebP、TIF/TIFF、BMP、GIF，以及 NEF/NRW、CR2/CR3/CRW、ARW/SR2/SRF、RAF、DNG、ORF、RW2、PEF、SRW、RWL、3FR、FFF、IIQ、KDC、DCR、MOS、MRW、X3F。文件选择器可筛选常见图片或相机 RAW。HEIC/HEIF、AVIF 暂未加入；GIF/WebP 动画和多页 TIFF 按第一帧/页浏览。

普通图片有 EXIF 时显示光圈、快门、ISO、焦距、拍摄时间、相机和镜头。缺失字段显示“—”；尺寸和文件大小仍可读，不用文件修改时间冒充拍摄时间。EXIF 的拍摄时间按相机记录显示，不推测时区。标记、批量选择/反选、回收站删除和直方图适用于所有格式，原文件不被改写。

JPG、PNG、WebP、BMP、GIF 直接交给浏览器解码原图，保留 EXIF 与 ICC；TIFF 转为保留 ICC 的全分辨率无损 PNG 预览并缓存，仍从源文件读取参数。普通图片显示“原图”，禁用 RAW 显影按钮。8 种 EXIF 方向在元数据尺寸、缩略图和主图保持一致。极大文件、复杂压缩或首次 TIFF 转换可能超过零点几秒；预加载与内存缓存仍保持启用。

RAW 优先提取相机内嵌预览（补足部分相机预览缺失的方向信息，不重新压缩 JPEG）。缺少可读预览时尝试 LibRaw 显影并缓存；这时首次打开可能需数秒。RAW 支持范围取决于机型和压缩方式，不等于所有同扩展名文件都能解码；不支持时显示错误，可继续浏览其他照片。部分 DNG 压缩方式需要当前构建未包含的可选解码器。预览可能小于传感器分辨率，100% 指当前图像像素；支持显影的文件可切换 RAW 检查原始分辨率细节。

0.3.0：详细页右栏顶部新增亮度 / RGB 直方图，默认亮度，下方曝光参数采用两列布局。窗口较矮时，其他参数自动改成紧凑行；已针对 900 × 600 窗口设计。沿用既有标记和缓存目录。

直方图基于正在显示的相机预览（或 RAW 显影后的预览），在独立 Worker 内将整图缩小到最长边 1024 像素后计算每通道 256 档。亮度使用 sRGB 编码值的加权 luma（0.2126 R + 0.7152 G + 0.0722 B），不代表线性 RAW 传感器曝光，也不用于精确统计原始过曝像素。缩放/平移不改变整图统计范围。计算不重新读原片，照片先显示，快速切图取消旧任务；内存最多缓存 256 份统计约 1 MiB，换来源清空。

0.2.0：总览新增“批量选择”。点击后才显示操作栏和勾选框；“选择已标记”选中本次来源内全部标记照片，“反选”翻转本次来源内所有照片的勾选，含屏幕之外的照片。“清空选择”只清空勾选；“完成”退出并保留原有标记。进入批量模式会显示全部照片。

“删除所选（N）”和 Delete 键都会确认本次选中的数量、已标记和未标记各多少张，然后移入回收站。部分失败时仅成功项移出列表，失败项保留勾选并列出原因，可以重试。确认框打开后不能改选，处理中不能重复提交或切换来源。

双击发布版 `NEFViewer.exe`。运行时不需要 Node.js、Rust 或 Python，需要 Windows WebView2 Runtime（多数 Windows 电脑已安装）。

每次启动选择文件夹或多张照片；顶部按钮可以重新选择。文件夹当前只扫描这一层，不递归子文件夹。总览双击照片进入详细，左侧缩略图切换照片。

- 左右方向键或底部箭头：上一张、下一张。
- 滚轮：以鼠标位置为中心缩放；拖动：平移。
- 空格或双击画面：适应窗口 / 100%；100% 按屏幕物理像素显示。
- 详细界面连续翻图保留倍率和相对查看位置。
- F：标记 / 取消标记；“已标记”按钮筛选。
- Enter：总览 / 详细。
- Delete：显示确认框，确认后移入 Windows 回收站；失败时不会永久删除。

## 读取与数据

RAW 优先直接提取内嵌的大幅相机 JPEG；后台预加载相邻照片，解码图像按约 384 MiB 预算缓存。缩略图使用虚拟列表，生成结果缓存到磁盘。标记独立存于 SQLite，不写回原片。

这批 Z5_2 样片内嵌预览为 6048 × 4032，竖拍自动旋转为 4032 × 6048，可以按预览的真实像素检查细节。它包含相机的锐化、降噪等处理，不能等同于未处理的 RAW。不同 NEF 的内嵌预览可能更小。

LibRaw 0.22.2 暂不能为所提供的 Z5_2 文件正确显影颜色，因此这批文件禁用 RAW 切换，明确显示“相机预览”。对解码器支持且有有效颜色矩阵的文件，可切换 RAW 显影；首次显影可能明显慢于相机预览，尚未用其他机型样本验收。

缓存和标记位置：`%LOCALAPPDATA%\NEFViewer`。`previews` 是可重新生成的缩略图；`library.sqlite3` 保存标记，请保留。程序启动时将磁盘预览缓存清理到 2 GiB 以下。文件身份使用路径、大小和修改时间；移动或修改原片后视作新文件。

## 开发

环境：Node.js LTS、Rust stable（MSVC）、Visual Studio Build Tools 的“使用 C++ 的桌面开发”、WebView2。

```powershell
npm install
npm run tauri dev
```

构建可执行文件：

```powershell
npm run build
cargo build --release --bin nef-viewer --features custom-protocol
```

结果位于 `target\release\nef-viewer.exe`。`custom-protocol` 不可省略，否则仍会寻找开发服务器。受限 Windows 子进程环境可用 `node scripts/build.mjs` 代替 Vite 构建（之前先执行 `npx tsc --noEmit`）。

测试：`cargo test --release --test library --test formats`。新增格式测试覆盖混合选择、EXIF 参数与日期、旋转方向、透明像素、无损 TIFF 预览、ICC 保留及损坏文件隔离。仅使用程序创建的临时假 NEF 测试来源选择、标记持久化、回收站删除和拒绝删除已被替换的文件，不对用户照片执行删除测试。

直方图测试（Node 24）：`node --test --test-isolation=none tests/histogram.test.ts tests/histogram-lifecycle.test.ts`。覆盖通道计数、亮度权重、尺寸采样、透明像素、大样本计数、取消/缓存/失败清理及来源切换。

`nef-bench` 是开发诊断程序，提供 inspect / bench / serve。serve 仅监听 127.0.0.1，所有端点只读；浏览器 QA 不提供真实标记和删除。使用 `?qa=1&demo=1` 可演示临时勾选和删除结果；`partial=1` 额外演示一次部分失败，仅改变浏览器内存。正式桌面程序始终调用真实 Tauri 命令，无需运行服务器。

## 导出验证

导出验证：`cargo test --release --test export` 覆盖 JPEG 质量/采样标记、全尺寸和方向、EXIF/ICC、透明背景、无预览 RAW、剪贴板位图载荷、ZIP 严格大小临界值、取消、坏片隔离、重名与源文件保护。`nef-bench export <来源文件夹> <已存在的输出文件夹> [测试分包上限字节数]` 可运行实际导出；serve HTTP 仍然只读。浏览器 `demo` 只模拟导出 UI，不写文件或剪贴板。
